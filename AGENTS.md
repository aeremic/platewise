# Platewise

Food diary calendar for iOS + Android. Log what you ate per day by category; each category is
green / orange / red, and each calendar day is colored by the average of its entries.
Local-only (SQLite), no accounts, dark theme with Liquid Glass.

## Stack

- Expo SDK 57 (React Native 0.86, New Architecture), TypeScript, Expo Router.
- Development builds only (`npm run ios` / `npm run android`), not Expo Go. `/ios` and `/android` are generated (prebuild) and git-ignored.
- No `expo-dev-client`: debug builds load JS from Metro (`npm start`). Don't start Metro with `--localhost` — the Android emulator reaches the host via IPv4 `10.0.2.2`.
- SQLite via `expo-sqlite` + Drizzle ORM. Schema: `src/db/schema.ts`. After changing it run `npm run db:generate` and commit the new files in `drizzle/`. Never edit an already-shipped migration.
- **Migrations must never lose user data**: only add nullable/defaulted columns, new tables, and data `UPDATE`/`INSERT`s. `src/db/__tests__/migrations.test.ts` fails on `DROP`/`DELETE`/`RENAME`/table rebuilds. Data migrations: `npx drizzle-kit generate --custom --name <name>`.
- Before pending migrations run, `src/db/backup.ts` copies the DB to `platewise-backup-<applied count>.db`.
- After adding/editing a `.sql` migration, **restart Metro** (`metro.config.js` keys the cache on SQL contents). A stale inlined migration crashes natively in `sqlite3_clear_bindings`.
- Glass: `src/components/glass/Glass.tsx` uses native `GlassView` on iOS 26+ and a translucent + gradient-highlight fallback elsewhere (Android has no native liquid glass).
- App icon & splash: generated by `swift scripts/generate-icons.swift` (PNG icons/splash in `assets/images`, SVG layers of the iOS 26 Icon Composer bundle `assets/platewise.icon`). Icon/splash changes need `npx expo prebuild --clean` and a native rebuild.

## Layout

- `src/app/` routes: `index` (calendar), `day` (form sheet: log/remove entries for a date, `?date=YYYY-MM-DD`), `categories/index`, `categories/[id]` (form sheet; `id=new` to create).
- `src/domain/` pure logic with unit tests (`npm test`). `health.ts` holds the day-color rule; reuse it for monthly stats.
- `src/data/` all database access. Screens read through `useLiveData` (`src/hooks/useLiveData.ts`), which re-queries when listed tables change.

## Decisions

- Health level is an integer: 0 red, 1 orange, 2 green. Day level = average of entries; ≥1.5 green, ≥0.75 orange, else red.
- Day color always uses the category's *current* health, so recoloring a category recolors past days (user's choice).
- Logging the same category twice = two entries; no servings.
- Dates are stored as local `YYYY-MM-DD` text, never timestamps.
- Removing a category: built-ins (with `seed_key`) and categories with entries are archived (`archived_at`, shown under Hidden, restorable); unused custom ones are deleted.
- "Restore defaults" resets to exactly the built-ins: custom categories are deleted, or marked `deleted_at` if they have entries (never shown again, but past days keep their color).
- Categories without an emoji show `FALLBACK_EMOJI` (🍽️) everywhere — use `categoryEmoji()`.
- Day sheet "Recent" row = active categories by most recent entry. A category created from the day sheet is auto-selected via `categoryEvents`.
- Nutrition (`src/domain/nutrition.ts`): categories store kcal / fiber / sugar **per portion** (+ `portion_label`); null = unknown (user-created categories start empty). Entries store `portions` and **snapshotted totals** when logged, so editing a category never changes past days (user's choice — unlike health colors). Entries with null values (e.g. logged before nutrition existed) fall back to category values × portions.
- Portion stepper scales the current values (including hand-edited ones) in 0.5 steps. Tapping a logged food opens `entry/[id]` (edit amounts or remove).
- Daily goals live in `daily_goals` as history (`effective_from`); a day uses the latest row on or before it. kcal and sugar are limits (max), fiber is a target (min); null = off. Progress shows on the home Today card.
- Built-in nutrition values are approximate; `DEFAULT_CATEGORIES` feeds new installs and "Restore defaults", `drizzle/0003_nutrition_defaults.sql` filled existing installs.
- Weeks start on Monday. UI language: English.
- Planned later: monthly statistics (aggregate `entries` joined to `categories` by month with `levelFromAverage`).

## iOS gotchas (found on device)

- Form sheet with a ScrollView: the sheet expects exactly `[header, ScrollView]` — give the header `collapsable={false}` or the ScrollView covers it. A `fitToContents` sheet must not contain any ScrollView (even a horizontal one); use wrapping grids instead.
- Don't make `GlassView` `isInteractive` inside a `Pressable`: native interactive glass swallows the first tap.
- Screens with `headerLargeTitle` must have the ScrollView as the root view (no wrapper), otherwise the title never collapses. Put decorative backgrounds inside the ScrollView.
